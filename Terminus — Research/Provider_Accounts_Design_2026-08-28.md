# Connected Provider Accounts — borrowing Codex + OpenCode credentials for the Terminus harness (2026-08-28)

**[live]** = verified by a real request from this machine on 2026-08-28; **[src]** = confirmed in upstream source.

## Decision
Model each usable credential as a `ProviderAccount` (vendor, auth kind, opaque kernel secret URI, base URL, wire protocol, host allowlist, discovered model catalog). Auto-detect `codex-chatgpt` (1 account, 9 models, ChatGPT Plus) and `opencode:<providerID>` (8 providers, 354 models; 7 free need no credential). Discovery, credential extraction, OAuth refresh, HTTPS dispatch all inside the Rust kernel; control plane and desktop see metadata only. Per-turn account selection replaces the fixed `direct > gateway > local` chain. **Rejected:** `codex app-server turn/start` — it would run Codex's loop/tools/sandbox and forfeit Terminus's context compiler, ACI, kernel, and evidence guarantees. We borrow the bearer token and catalog, nothing else.

## Part 1 — Codex / ChatGPT subscription wire (measured)
- Endpoint `POST https://chatgpt.com/backend-api/codex/responses` — Responses API, SSE. [live 200]. Base URL constant `codex-rs/model-provider-info/src/lib.rs:40`; selected by `AuthMode::Chatgpt` (`:292-306`). Codex prefers WebSocket (`wss://…/responses`, `OpenAI-Beta: responses_websockets=2026-02-06`) with HTTP+SSE fallback; we use HTTP+SSE.
- Headers: only `Authorization: Bearer <access_token>` was required on a single-workspace Plus account [live]. Send: `Authorization`, `ChatGPT-Account-ID`, `originator: terminus`, `User-Agent: terminus/<ver>`, `version`, `session-id`, `Accept`, `Content-Type`. `OpenAI-Beta: responses=experimental` is NOT in codex 0.150.1 (stale third-party artifact).
- Body contract [all live]: `store:true`→400 "Store must be set to false"; `stream:false`→400; `max_output_tokens`, `temperature`, `top_p`, `previous_response_id` → 400 "Unsupported parameter"; `input` as string → 400 "Input must be a list"; `instructions` optional; `text.verbosity`, `include:["reasoning.encrypted_content"]`, `prompt_cache_key`, `reasoning:{effort,summary}`, function tools → 200; `model:"gpt-4o"` → 400 "not supported when using Codex with a ChatGPT account". Chat-style `[{role,content}]` input accepted — Terminus's `renderResponsesRequest` (`packages/provider-openai/src/index.ts:402-431`) output works after stripping four fields.
- SSE: `response.created → in_progress → output_item.added → content_part.added → output_text.delta… → output_text.done → content_part.done → output_item.done → completed`; function calls via `response.function_call_arguments.delta/.done`. Usage `{input_tokens, input_tokens_details:{cache_write_tokens,cached_tokens}, output_tokens, output_tokens_details:{reasoning_tokens}, total_tokens}` — matches `provider-openai/src/stream.ts:133-148`. Decoder gap: add `response.reasoning_summary_text.delta/.done`, `response.reasoning_summary_part.added`, `response.incomplete`.
- Rate-limit headers [live]: `x-codex-active-limit`, `x-codex-plan-type`, `x-codex-primary-used-percent|window-minutes|reset-after-seconds|reset-at`, `x-codex-secondary-*` (same), `x-codex-primary-over-secondary-limit-percent`, `x-codex-credits-has-credits|balance|unlimited`, `x-codex-turn-state` (opaque sticky routing). Parser `codex-api/src/rate_limits.rs:23-101`. Terminus can't see these today: `ConnectorResponseMessage` (`proto/terminus/kernel/v1/kernel.proto:769-773`) carries no headers.
- Catalog: `GET https://chatgpt.com/backend-api/codex/models?client_version=0.150.1` with Bearer only → 9 models with `slug, display_name, visibility, context_window, max_context_window, auto_compact_token_limit, default_reasoning_level, supported_reasoning_levels[], supports_reasoning_summaries, support_verbosity, input_modalities, supports_parallel_tool_calls, service_tiers, base_instructions` + `ETag`. Observed: gpt-5.6-sol/terra/luna (272k/872k; efforts low…ultra/max), gpt-daybreak-blue-latest, gpt-reserve (hidden), gpt-5.5, gpt-5.4 (272k/1M), gpt-5.4-mini, codex-auto-review (hidden). Catalog identical across `originator` values [live] — do not design around #40258.
- Credentials: `~/.codex/auth.json` 0600 `{auth_mode, OPENAI_API_KEY, tokens:{id_token, access_token, refresh_token, account_id}, last_refresh}`. access_token RS256 `exp−iat` = 10 days; id_token 1 h; claim `https://api.openai.com/auth` has `chatgpt_account_id` (= `tokens.account_id`), `chatgpt_plan_type`. Refresh: `POST https://auth.openai.com/oauth/token` JSON `{client_id:"app_EMoamEEZ73f0CkXaXp7hrann", grant_type:"refresh_token", refresh_token}` → `{id_token?, access_token?, refresh_token?}` — refresh tokens ROTATE (write back). Trigger: `exp ≤ now+5min`, or `last_refresh < now−8d`, or 401.
- **Preferred credential path: `codex app-server` stdio NDJSON** [live]: `initialize{clientInfo:{name:"terminus",…}}` → `initialized` → `account/read{refreshToken:false}` → `{account:{type:"chatgpt",email,planType:"plus"}}`; `getAuthStatus{includeToken:true,refreshToken:bool}` → `{authMethod:"chatgpt", authToken:<JWT byte-identical to auth.json>}`; `model/list{includeHidden:true}` → models with `supportedReasoningEfforts`, `defaultReasoningEffort`, `hidden`; `account/rateLimits/read` → primary/secondary windows + credits + planType. No OAuth implementation needed; no auth.json write race. Caveats: `getAuthStatus` marked deprecated in v1 protocol; stdio unauthenticated; `clientInfo.name` becomes the process-global `originator`. Fallback: read auth.json in the kernel, refresh kernel-side, write rotated refresh token back at 0600.

## Part 2 — OpenCode
- `~/.local/share/opencode/auth.json` 0600; union `{type:"oauth", refresh, access, expires(ms), accountId?, enterpriseUrl?} | {type:"api", key, metadata?} | {type:"wellknown", key, token}` (Effect Schema, undecodable entries dropped). v2 SQLite `credential` table empty on 1.18.x. `OPENCODE_AUTH_CONTENT` env bypass exists.
- Provider → URL/protocol from Models.dev (`https://models.opencode.ai/api.json` ≡ `https://models.dev/api.json`, 4,428,570 bytes, 207 providers / 7,488 models). Provider `{id,name,env[],npm,doc,api?,models{}}`; model `{id,name,reasoning,tool_call,limit{context,output},cost{input,output,cache_read?,cache_write?},status?,…}`. Resolution: `config.provider[id].options.baseURL` → `provider.api` → SDK default (`provider.ts:1755-1777`).
- Configured here: cerebras (SDK default, `@ai-sdk/cerebras`), nvidia `https://integrate.api.nvidia.com/v1`, huggingface `https://router.huggingface.co/v1`, cloudflare-workers-ai `https://api.cloudflare.com/client/v4/accounts/${CLOUDFLARE_ACCOUNT_ID}/ai/v1` (accountId from `metadata.accountId`), ollama-cloud `https://ollama.com/v1`, zenmux `https://zenmux.ai/api/v1`, baseten `https://inference.baseten.co/v1`, opencode `https://opencode.ai/zen/v1` — all chat_completions. `packages/provider-zen/src/catalog.ts:223-234` already maps npm→protocol (`openai-compatible`→chat, `@ai-sdk/openai`→responses, `@ai-sdk/anthropic`→messages, else fail closed). Mirror OpenCode filters: drop `deprecated`, `alpha` unless opted in, providers with zero models.
- **Free Zen models need no credential** [live]: `POST /zen/v1/chat/completions {"model":"big-pickle"}` no auth → 200 `"cost":"0"`; `"nemotron-3-ultra-free"` → 200; composite id `"opencode/big-pickle"` → 401 ModelError (**use bare ids**); paid `claude-haiku-4-5` → 401 "Missing API key"; `GET /zen/v1/models` → 64 models; `/zen/go/v1` = Go plan tier, no anonymous access. IP-rate-limited, resets 00:00 UTC. Why `opencode models` lists 7 `opencode/*` without a key: `provider.ts:185-206` keeps only `cost.input===0` non-deprecated models with sentinel `apiKey:"public"`. Terminus's anonymous-Zen path (`gateway-provider-config.ts:96-102`) is already correct.
- **Do not depend on `opencode serve`**: `GET /config/providers` returns plaintext keys and `PUT /auth/{id}` accepts unauthenticated writes when `OPENCODE_SERVER_PASSWORD` unset [live].

## Part 3 — Blockers in Terminus today
1. Keyring admits only `secret://opencode/zen|go` (`crates/terminus-secrets/src/keyring_provider.rs:85-92`; registered under `opencode` only, `services.rs:177-180`) → `secret://direct/*` path is orphaned. `store()` rejects whitespace, caps 16 KiB.
2. Connector header allowlist is `accept, content-type, anthropic-version` (`crates/terminus-connector/src/broker.rs:503`); `AuthStyle` = Bearer|NamedHeader|None; request/response bounds 1 MiB (`broker.rs:80-81`).
3. Offline Models.dev snapshot is an 8 KB fixture (5 providers, 17 models, invented ids); no refresh tooling; `admitDirectModelRecord` rejects modern models.
4. Egress allowlist is `opencode.ai:443` only (`services.rs:105-118`).
5. `tools/standalone-check.ts:96` regex matches `/opencode/` in shipped artifact text: `secret://opencode/cerebras`, `opencode/big-pickle`, `OPENCODE_HOME` all match; `opencode:cerebras` does not. Rules: colon-form sources, `secret://provider-account/<uuid>`, no `*-opencode` package/path names, keep host strings in Rust. `just standalone-check` currently fails on stale `apps/desktop/release/` artifacts (migrations 0007/0009/0011/0018 contain `secret://opencode/zen`).
6. Turn selection is a fixed ternary chain (`index.ts:12729-12786`, `:13345-13357`, `:6982-7014`); desktop model choice mutates the singleton gateway row (`use-model-routing.ts:40-54`).
7. `tools/boundary-check.ts` forbids fs/process/env-secret access in `packages/*` → discovery must be Rust.

## Part 4 — Design
- **`ProviderAccount`** `{id, source: "codex-chatgpt"|"opencode:<id>"|"zen"|"direct-openai"|"direct-anthropic", displayName, authKind, credentialUri ("" = anonymous), baseUrl, protocol, renderProfile, hostAllowlist, connectorId, models[], status: connected|expired|error|installed_not_signed_in|not_installed, statusDetail, lastVerifiedAt, expiresAt, billing: subscription|free|paid|unknown, usage, revision}`; `ProviderAccountModel` mirrors `GatewayModel` + `reasoningEfforts[]`, `defaultReasoningEffort`, `hidden`, `billing`, `catalogSource`. Table `provider_accounts` replaces the singleton gateway row (migrated as one `zen` account). Subscription billing = zero micros → must be guarded by the quota meter, not `BudgetGuard`.
- **Kernel `ProviderAccountService`**: `DiscoverLocal`, `Import`, `Refresh` (proto sketch in agent report) requiring `OperationClass::Secret` scoped to the capability URI. Codex: spawn `codex app-server` via `ProcessManager` (≤15 s, bounded output), run the RPC sequence, decode JWT in-kernel, store compact JSON `{access_token, account_id}`; fallback to auth.json + kernel-side refresh with write-back. OpenCode: read auth.json, store per provider; v1 skips oauth-type providers.
- **Catalog**: Codex via `model/list` (zero egress) or `/models` through the connector; OpenCode providers via models.dev; Zen unchanged. Add `just refresh-model-catalog` → real snapshot with `_meta`, `codegen-check` assertion.
- **Routes**: `GET /v1/provider-accounts`, `POST /v1/provider-accounts/discover`, `POST /v1/provider-accounts`, `POST /v1/provider-accounts/:id/refresh`, `DELETE /v1/provider-accounts/:id`, `PUT /v1/provider-accounts/default`; `GET /v1/provider-models` multi-account (additive: `account_id`, `billing`, `reasoning_efforts`); `POST /v1/turns` + `{provider_account_id?, model?, reasoning_effort?}` (unknown account → 409, no fallback).
- **Turn selection**: `resolveTurnProvider({requested, sessionDefault, globalDefault, accounts})` → typed error, never silent; per-session `TurnProviderSelection`; capability token scoped to exactly one host + one secret.
- **Rendering**: `renderChatGptCodexRequest` = `renderResponsesRequest` then delete `max_output_tokens|temperature|top_p|previous_response_id`, force `store:false`, `stream:true`, `include:["reasoning.encrypted_content"]`, `prompt_cache_key`, `tool_choice:"auto"`, `parallel_tool_calls`, `reasoning:{effort,summary:"auto"}`, `text.verbosity`; `continuation.nativeId=false` for this profile. Effort: clamp UI `low|medium|high|max` into the model's advertised levels (max → highest of ultra/max/xhigh/high). Generalize `provider-zen` (`providerId: string`, per-account baseUrl, export `protocolForPackage`, per-account host/path allowlist in `KernelGatewayClient`); keep package name.
- **Kernel changes**: descriptor `allowed_request_headers` + `static_headers` (pin `originator: terminus`, `version` kernel-side); `response_headers` on the receipt with per-connector allowlist (`x-codex-*`, `x-models-etag`, `retry-after`); per-descriptor bounds 8 MiB / 32 MiB; keyring namespace `provider-account` by UUID pattern; egress policy derived from connected accounts (opencode.ai floor).
- **UI**: picker grouped by account with Subscription/Free/price badges and per-model efforts; expired accounts greyed with reason; selection writes the session default. Settings → Connected accounts (status line, usage windows, models, Refresh/Set default/Disconnect, Detect, detected-but-unconnected list). First run: one non-modal "found your ChatGPT subscription and 7 OpenCode providers — connect?" card; explicit opt-in, never auto-import.
- **Security/ToS**: tokens never leave the kernel; extend `Redactor` to scrub `chatgpt_account_id`; delete secret before row on disconnect; honest `originator: terminus` pinned in kernel; no multi-account pooling; prefer app-server surface; UI disclosure that OpenAI has published no policy on third-party subscription use (Anthropic banned the equivalent); support `codex login --with-access-token` / API-key alternatives.
- **Plan (≈21–27 d)**: 1 kernel connector capabilities (2–3 d) → 2 keyring + ProviderAccountService (4–5 d) → 3 catalog refresh (1 d, independent, first) → 4 domain + routes (3–4 d) → 5 chatgpt-codex profile + decoder goldens (2–3 d) → 6 generalize provider-zen (2 d) → 7 turn selection (3–4 d) → 8 desktop (4–5 d). Slices 1/2/4 touch secrets/auth/network → targeted security suites + two approvals per AGENTS.md. Pre-work: clear stale `apps/desktop/release/` so `just standalone-check` is usable.
