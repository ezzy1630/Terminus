# OpenCode Retained Capabilities Inventory

Per SPEC §6, §42.2, ADR-0002: Terminus is bootstrapped from an immutable pinned OpenCode commit (`184da0e42edc12ea480d09c6620512f8b7a0e656`). ## Detailed Capability Specifications

### 1. Session Continuity
- **OpenCode Baseline:** Session history stored as JSON event trajectories with continuation tokens.
- **Terminus Contract:** Sessions map to Agent Runtime Protocol (ARP) session objects. The OpenCode bridge translates legacy `session.create`, `session.resume`, and `session.get` into canonical Terminus session events.
- **Verification:** Golden session state resumption test in `packages/open-code-bridge/src/parity.test.ts`.

### 2. Provider Adapters & 3. Request Rendering
- **OpenCode Baseline:** Direct HTTP request construction for Anthropic, OpenAI, Google Gemini, and local providers.
- **Terminus Contract:** All prompt rendering uses Context IR (`@terminus/context-ir`). The bridge verifies that provider payloads generated by OpenCode adapters match Terminus golden request schemas.
- **Verification:** Golden request payloads (`anthropic-messages.json`, `openai-chat.json`, `google-gemini.json`) validated in `packages/open-code-bridge/src/parity.test.ts`.

### 4. Model Discovery
- **OpenCode Baseline:** Dynamic fetching and static fallback catalogs for models and token limits.
- **Terminus Contract:** Retained catalog resolution adapter in `@terminus/model-router`, providing model capabilities, pricing, and window boundaries.

### 5. MCP & Skill Behavior
- **OpenCode Baseline:** MCP server stdio/sse connectors and markdown skill definitions.
- **Terminus Contract:** MCP descriptors are hashed and pinned by `@terminus/capability-registry`. Inherited skills are imported without ambient process execution permissions.

### 6. Terminal Interaction & 8. Bounded Tool Output
- **OpenCode Baseline:** PTY spawn and string truncation.
- **Terminus Contract:** All process spawns must route through Rust kernel RPC (`terminus.kernel.v1`). Bounded output truncates at byte limits (default 4096 bytes) and provides tail inspection and continuation tokens. Never silent.

### 7. LSP Integration
- **OpenCode Baseline:** Subprocess LSP initialization (`tsserver`, `gopls`, `pyright`).
- **Terminus Contract:** LSP processes are run with kernel-granted capability tokens restricting filesystem access strictly to active workspace paths.

### 9. Authentication
- **OpenCode Baseline:** `process.env` inspection for `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`.
- **Terminus Contract:** Tracked as `BYPASS-0004` (SECRET_USE). Secrets are brokered; raw credentials are never exposed in prompt logs, trajectories, or unisolated subprocesses.

### 10. Generated SDK/API Behavior & 11. Configuration Semantics
- **OpenCode Baseline:** REST and WebSocket server routes, `opencode.json` configuration resolution.
- **Terminus Contract:** `@terminus/open-code-bridge` translates incoming legacy requests into Terminus Public API calls (`@terminus/public-api`). Config semantics map `opencode.json` settings onto `terminus.config.yaml`.

### 12. TUI Behavior
- **OpenCode Baseline:** Ink/TUI terminal interface with interactive prompts.
- **Terminus Contract:** Retained UI state machine isolated from kernel effect execution.

## Strangler Exit Criteria

The OpenCode substrate is fully replaced when:
1. Every entry in `docs/security/effect-bypass-register.yaml` reaches status `removed`.
2. `@terminus/open-code-bridge` operates strictly as a zero-effect adapter translating public API formats.
3. `upstream/divergence-budget.yaml` tracks 0 modified files in inherited core logic.
4. All 12 capability areas pass current x pinned parity tests without accessing OpenCode internal singletons.
