# Terminus overhaul risk register

| ID | Risk | State | Mitigation/evidence |
| --- | --- | --- | --- |
| RISK-001 | Completion, checkpoint, or terminal publication can diverge after a crash. | MITIGATED WITH RESIDUAL | After checkpoint preparation succeeds, checkpoint admission, checkpoint/terminal events, checkpoint `COMMITTED` state, and turn `COMPLETED` state commit in one transaction; preparation failure still follows an explicit best-effort fallback, and later recovery boundaries remain open. |
| RISK-002 | Metadata-only compaction can hide source episodes. | MITIGATED WITH RESIDUAL | Source body and immutable artifact provenance are required, summary failure/cancellation retains sources, and production has an atomic commit callback; DB replay coverage remains open. |
| RISK-003 | Repair allowance may renew across turns. | MITIGATED WITH RESIDUAL | Durable repair-event count, stored budget, zero-preserving configuration, failure signatures, and a fenced `RepairAttempt` lease seed one cumulative controller; repair metrics and broader crash coverage remain. |
| RISK-004 | Ambiguous provider/effect operations can duplicate cost or side effects after restart. | OPEN | Ambiguous v1 effects now atomically become tool `UNKNOWN` plus effect `MANUAL_REVIEW`, emit deterministic recovery evidence, skip already-settled rows, and never retry blindly. Provider request fingerprints/IDs, trusted kernel receipt reconciliation, and full fault-injection proof remain required. |
| RISK-005 | Read-only tools may be treated as mutation by name fallback. | MITIGATED WITH RESIDUAL | Engine budgeting uses the tool catalog side-effect class and focused tests cover read/write paths; durable operation-ledger coverage remains open. |
| RISK-006 | Advanced systems add cost without verified value. | OPEN | Scout is default-off and the eval registry requires paired multi-seed/holdout evidence; no promotion evidence exists. |
| RISK-007 | Local green tests can be mistaken for release proof. | MITIGATED WITH RESIDUAL | Evidence ledger separates local, hosted, live-provider, signed, and holdout results; hosted and live proof remain absent. |
| RISK-008 | Schema changes can break existing sessions. | OPEN | State values and event contracts are additive in this slice; migration, previous-state, and rollback drills remain required. |
| RISK-009 | Broad `index.ts` edits can conflict with existing work. | MONITORED | Exact checkout was clean at start; only task-owned paths are being staged and the final diff must be reviewed before handoff. |
| RISK-010 | Provider SDK or web behavior can drift. | OPEN | Provider-specific wire code stays isolated and stream tests pass; current live conformance fixtures are not available. |
| RISK-011 | Recovery may replay or lose `RESPONSE_VALIDATING`/`VERIFYING` work. | OPEN | Recovery resumes unambiguous pre-provider/tool boundaries and quarantines unsafe terminal-adjacent states; response/verification continuation needs durable checkpoints and fault tests. |
| RISK-012 | Repair parent/child association can be stranded or duplicated. | MITIGATED WITH RESIDUAL | Durable attempt/lease identity, transactional child association, parent supersession, and DB-backed idempotent replay/fencing tests are present; later repair boundaries and provider/effect replay remain open. |
| RISK-013 | Automatic checkpoint failure can leave a completed turn without continuity. | MITIGATED WITH RESIDUAL | Failure is explicit as `context.auto_checkpoint_failed` and never silently treated as success. When preparation succeeds, checkpoint and terminal publication are atomic and startup defers the coupled PREPARED row for terminal recovery; preparation failure remains best-effort and may leave a completed turn without continuity. |
| RISK-014 | Remote branch protection and hosted release evidence are weaker than the target. | OPEN | Dry-run/apply/verify tooling exists; read-only verification found ruleset `21228252` missing approval/code-owner requirements and containing a repository-role bypass. |
| RISK-015 | Direct state writes in the composition root can bypass the canonical transition table. | OPEN | Domain transition table and CAS updates exist, but all live writers are not yet routed through one transition owner. |
| RISK-016 | Instruction discovery can miss relevant nested or unusual repository scopes. | OPEN | Kernel-read discovery covers changed/scope-derived directories and precedence; full repository map/invalidation/symlink coverage remains open. |
| RISK-017 | Branch admission and completion-record persistence are separate crash boundaries. | MITIGATED WITH RESIDUAL | Completion intent is persisted as `PREPARED` before branch admission, committed atomically with task/turn admission, and replayed only from an `ADMITTED` branch. DB-backed rollback/replay/quarantine tests pass; provider/effect ambiguity and full fault-matrix proof remain. |
